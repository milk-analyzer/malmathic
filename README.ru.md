# malmathic

Офлайн-триаж заражённых машин Windows: сам читает сырой NTFS и кусты реестра, ранжирует файлы-кандидаты по уликам и восстанавливает байты образца. Ничего не монтирует, не запускает и не передаёт.

## Возможности

- Работает на живой системе с правами администратора, из консоли WinRE на машине, которая не загружается, и по образу диска (`dd`, VDI, VMDK с цепочками снапшотов).
- Разбирает `$MFT`, USN-журнал, Amcache, ShimCache, prefetch, PCA, UserAssist, планировщик задач, ключи Run и ярлыки автозагрузки, журнал и карантин Defender, корзину, mark-of-the-web и структуру PE (imphash, Rich header) внутри процесса — без Windows API на пути анализа, поэтому заблокированные файлы и несмонтированные кусты читаются всё равно.
- Оценивает кандидатов как сумму логарифмов отношений правдоподобия поверх априорной вероятности, зависящей от машины; каждая строка улик печатается со своим весом, а `malmathic explain` показывает обоснование каждого.
- Восстанавливает образец из живого файла, карантина Defender, корзины, теневой копии, кластеров удалённой записи `$MFT`, слака индексов, осиротевших записей, неиспользуемого хвоста переиспользованной записи `$MFT` и образа записи, ещё лежащего в `$LogFile`; каждое восстановление помечается `VERIFIED`, `UNVERIFIED` или `PARTIAL`.
- С `--deep` вырезает файлы из свободного места по хэшу, а для файла, чей хэш нигде не записан, — по имени, которое образ несёт внутри себя (каталог отладки или таблица экспорта).
- Проверяет подписи Authenticode и каталогов офлайн по встроенным корневым сертификатам.
- Обезличивает отчёты для публикации (`--redact`, `malmathic redact`).
- Привязки для Python (`pymalmathic`): парсеры, анализ PE, чтение образов.

## Установка

Скачайте `malmathic.exe` для x86-64 или ARM64 со страницы [Releases](https://github.com/milk-analyzer/malmathic/releases): один статический файл около 4 МБ, без рантайма.

Из исходников: Rust 1.94+ с тулчейном MSVC, `cargo build --release`.

Чтение подключённого тома требует прав администратора (в WinRE они уже есть). Чтение образа — не требует ничего.

## Использование

```
malmathic                                   триаж найденного тома с Windows; дело — в cases\ на диске инструмента
malmathic --out D:\case                     каталог дела по вашему выбору
malmathic --image disk.vmdk --out D:\case   образ диска; --out обязателен
malmathic --redact                          дополнительно записать report.redacted.*
malmathic explain <feature>                 вес и обоснование признака
malmathic redact D:\case\report.json        обезличить готовый отчёт
```

При запуске двойным щелчком («Запуск от имени администратора») показывает каталог дела и ждёт Enter или другой путь.

Коды выхода: `0` — анализ выполнен и дело записано (отрицательный результат — тоже результат); `1` — остановка до записи (нет прав, нет тома с Windows, отвергнутое размещение) либо отчёт не удалось записать; `diag` и `redact` возвращают `2` при ошибке использования или отвергнутом пути вывода.

### Флаги

| Флаг | |
| --- | --- |
| `-o, --out <КАТАЛОГ>` | Каталог дела. По умолчанию `cases\<том>-<время>` на диске, где лежит exe; с `--image` обязателен. Отвергается, если уже содержит результат, лежит в дереве исходников или в папке самого exe (для exe в корне диска — в самом корне), а с `--deep` — на читаемом томе. |
| `--overwrite-case` | Заменить существующий каталог дела. |
| `--volume <V>` | Какой том разбирать: буква диска или часть GUID тома. |
| `--image <ФАЙЛ>` | Образ диска вместо устройства; тип по заголовку, прав не нужно. Не монтируйте его сами. |
| `--list-volumes` | Перечислить тома и что на них найдено (stderr), выйти. |
| `--list-snapshots` | Вместе с `--image`: напечатать цепочку снапшотов VMDK, выйти. |
| `--no-samples` | Восстановить и захешировать, но не записывать вредонос в каталог дела. |
| `--deep` | Дополнительно вычитать нераспределённые кластеры для кандидатов без байтов — по записанному хешу или по имени, которое образ несёт внутри себя. Медленно. |
| `--acquire-top <N>` | Не более N верхних кандидатов на восстановление (по умолчанию 10), только выше порога отчётности. |
| `--verify-top <N>` | Насколько глубоко по списку проверять подписи (по умолчанию 200). |
| `--redact` | Дополнительно записать `report.redacted.txt` и `report.redacted.json`. |
| `--json` | Печатать в stdout JSON-отчёт вместо текстового. |
| `--quiet` | Не печатать ход по стадиям в stderr. |
| `--pause`, `--no-pause` | Принудительно ждать или не ждать Enter в конце (`--no-pause` также убирает вопрос о каталоге дела); по умолчанию — только если окно закроется. |

### Подкоманды

| Команда | |
| --- | --- |
| `explain [FEATURE...]` | Таблица весов или одна строка: смысл признака, обоснование веса, частота на чистых машинах. |
| `redact <REPORT.JSON> [--out ФАЙЛ] [--overwrite] [--keep-urls]` | Пишет `<имя>.redacted.json` и `.txt`: пользователи → `user1`…, машины → `host1`…, домены SID, идентификаторы и серийники томов перенумерованы, e-mail и IP замаскированы, URL обрезаны до хоста, путь дела удалён. Одно имя — один псевдоним во всём отчёте. |
| `diag mft [PATH] [--record N] [--children]` | Одна запись `$MFT` со всеми предками; находит устаревшие ссылки на родителя. |
| `diag attribute-lists [--follow]` | Перепись записей с `$ATTRIBUTE_LIST`. |
| `diag lzx-capture --out <ФАЙЛ> [--overwrite] [--mount ROOT] [--all-algorithms] [--limit N]` | Снять потоки Compact-OS вместе с открытым текстом (WinRE). |
| `diag lzx-describe <ФАЙЛ>` | Описать такой снимок. |

### Каталог дела

| Путь | |
| --- | --- |
| `report.txt`, `report.json` | Ранжированные кандидаты с уликами и весами, находки по тому, покрытие — что прочитать не удалось. |
| `report.redacted.txt`, `report.redacted.json` | Обезличенные копии. Их и прикладывайте к issue. |
| `sample/C<id>.bin` | Восстановленные байты кандидата — живой вредонос; антивирус его изолирует, это ожидаемо. При `--no-samples` отсутствует. |
| `sample/unranked/` | Восстановления, до которых ранжирование не дотягивается: удалённые записи с runlist, исчезнувшие исполняемые из временных каталогов, имена из слака индексов, вычитки ниже порога. Лимит 64 файла или 256 МБ. |

## Гарантии, закреплённые тестами

- В поставляемых исходниках нет создания процессов, загрузки библиотек, монтирования и сетевых API; единственный `DeviceIoControl` — запрос длины; `Cargo.lock` совпадает с аудированным списком зависимостей.
- Читатели образов не держат записываемых дескрипторов; с `--deep` каталог дела на читаемом томе отвергается.
- Хеши `imphash` и Rich header совпадают с `pefile` правило в правило, включая замороженные таблицы ординалов и эвристики для упакованных образцов; Python-тесты сверяют их с `pefile`.
- Каждый парсер переживает усечённый, самоссылающийся, лгущий о размерах и нулевой ввод.

## Ограничения

- Веса — экспертные оценки, не подогнанные к размеченному корпусу; каждый отчёт об этом говорит.
- Априорная вероятность — один к числу кандидатов на машине: улики, достаточные на маленькой машине, на большой могут не хватить.
- Корректно подписанный вредонос получает штраф за подпись; украденный сертификат перебивает самый сильный отрицательный вес.
- Удалённый файл без записанного хеша всё ещё можно найти по имени, которое несут его собственные PE-заголовки, но тогда ничто не подтверждает, что байты принадлежат именно ему, а не другой копии той же программы.
- Атрибуты, восстановленные из слака записи или `$LogFile`, привязаны к пути одним лишь уцелевшим именем; доказательством это делает только совпадающий хеш, которого обычно нет.
- Только диск и реестр: ни процессов, ни памяти, ни сети; лечения нет.
- На живой системе руткит пользовательского режима может фильтровать чтение; WinRE и образы этого лишены.
- Только Windows.

## Привязки для Python

```
cd bindings\python
pip install maturin pefile
maturin build --release
pip install target\wheels\pymalmathic-0.1.0-cp39-abi3-win_amd64.whl
```

```python
import pymalmathic as mm
mm.parse_amcache(hive)          # parse_shimcache, parse_prefetch, parse_tasks, parse_defender_log, parse_persistence, parse_recycle_bin, analyze_pe
mm.imphash(pe); mm.imports(pe); mm.rich_header(pe)
img = mm.Image("disk.vmdk"); img.list_dir("\\Users"); img.read_file(path, max_bytes=64 << 20)
```

Отдельный cargo-workspace, чтобы PyO3 не попадал в аудированное дерево зависимостей. Одно `abi3`-колесо для CPython 3.9+, с type stubs. Парсеры возвращают словари наблюдений в формате `report.json`.

## Разработка

| Крейт | |
| --- | --- |
| `mm-core` | Кандидаты, наблюдения, пути, хеши, декодеры LZX и Xpress |
| `mm-raw` | NTFS: `$MFT`, индексы и слак, USN-журнал, теневые копии, WOF |
| `mm-env` | Тома, образы `dd`/VDI/VMDK, цепочки снапшотов, тип файла «только чтение», слой Win32 |
| `mm-harvest` | Парсеры артефактов, PE, imphash, Rich header, детектор массового шифрования |
| `mm-sign` | Проверка Authenticode и каталогов, встроенные корни |
| `mm-score` | Граф кандидатов, зоны, признаки, таблица весов, окно инцидента, базовая линия |
| `mm-report` | Модель отчёта, текстовый рендер, обезличивание |
| `malmathic` | Конвейер, цепочка восстановления, CLI, диагностика |
| `bindings/python` | `pymalmathic` |

```
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Обоснование каждого веса лежит в [`crates/mm-score/rules/weights.toml`](crates/mm-score/rules/weights.toml). См. [CONTRIBUTING.md](CONTRIBUTING.md) и [SECURITY.md](SECURITY.md).
