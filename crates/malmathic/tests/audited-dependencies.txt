# Every package in Cargo.lock, as audited on 2026-08-27.
#
# The audit that produced this list asked one question of each crate's own
# source: does it execute anything, load a library at runtime, mount a
# filesystem, or open a socket? The answer across the whole runtime tree was
# no. The only `std::process::*` calls anywhere in the tree that ships are
# `abort` (bytes, spin) and `exit` (clap, on a bad command line); no crate in
# the tree contains a `std::process::Command` outside its own tests and build
# scripts.
#
# Build-time and dev-time only, and therefore never in the shipped binary:
# `cc` and `find-msvc-tools` (which do spawn a compiler, at build time),
# `skeptic`, `pulldown-cmark`, `walkdir`, `tempfile`, `glob`, `same-file`,
# `cargo_metadata`, `cargo-platform`, `semver`, `camino`, `shlex`, `bytecount`,
# `error-chain`, `version_check`, `autocfg`, `rustversion`, `rustix`, `libc`,
# `errno`, `fastrand`, `linux-raw-sys`, `find-msvc-tools`, and the `wasm-*`,
# `wasi*`, `js-sys`, `android_*`, `core-foundation-sys` and `iana-time-zone-*`
# families, which are other platforms' code and are not compiled here at all.
#
# `crates/malmathic/tests/no_execution_no_mounting.rs` compares this list
# against Cargo.lock on every run. If it fails, a dependency entered or left
# the tree: audit the new one for the four questions above and then update this
# file. Do not update it to make the test pass.
